로터리 엔코더 입력 누락 및 다중 오입력

hardware.ino · PinChangeInterrupt
문제
초기에는 loop() 안에서 주기적으로 센서 값을 읽는 풀링(Polling) 방식으로 엔코더를 처리해, 다이얼을 빠르게 돌리거나 접점이 튈 때 입력이 빠지거나 한 번에 여러 번 중복 입력되는 현상이 발생.
해결

02

배율 · 사거리 연동 탄착 마커 스케일 보정

Scope.cs → Tagger.cs
문제
처음에는 탄착 지점에 이미지만 띄우고 스코프 배율(zoomRatio)에만 맞춰 스케일을 조정(Lerp)했더니, 목표물 거리가 달라질 때마다 화면 내 마커 비율이 일정하지 않게 커지거나 작아지는 문제가 발생.
해결
계산 위치를 Tagger 로 옮겨 사거리(dist)와 스코프 배율(Scope.ZOOM)을 함께 반영(0.03f × dist / Scope.ZOOM)해 거리에 상관없이 일정한 비율로 표시되도록 보정하고, 미충돌 시에는 마커를 비활성화해 잔상을 제거.

시스템 구조

  1. 01
    하드웨어 입력 Arduino Uno

    360도 로터리 엔코더 3개(영점·편향·디버깅용 시차)와 회전(줌)·슬라이드(장전) 가변저항 신호를 수신

  2. 02
    인터럽트 & 노이즈 필터링 enc_table (ISR)

    PinChangeInterrupt ISR이 상태표로 바운싱(delta=0)을 걸러 1클릭 4스텝(value/4)을 정규화하고, 가변저항은 데드존(줌 >1 · 슬라이드 >3)으로 떨림 억제

  3. 03
    변경분 시리얼 송신 20ms · 9600 baud

    값 변화가 발생한 센서 키만 "E:10;W:-2;R:80" 형식으로 조합해 20ms 주기로 USB 시리얼 송신

  4. 04
    논블로킹 수신 & 델타 이벤트 ArduinoConnection · SensorDataUpdateEvent

    Update() 에서 BytesToRead 로 대기 없이 1바이트씩 읽어 '\n' 단위로 파싱하고, 변경된 키(_curData)만 UnityEvent로 전달

  5. 05
    볼트 액션 · 스코프 · 탄착 보정 Scope · Cylinder · Tagger

    Lerp 보간으로 스코프 FOV·다이얼·실린더 Z축을 동기화하고, 사거리·중력·바람 기반 탄착 가이드 렌더링

개발 사항

  • 조준 이동은 VR 컨트롤러 트래킹, 스코프 영점(E)·편향(W)·배율(Z)과 장전(R)은 아두이노 우노 기반 360도 로터리 엔코더 3개(시차 P는 디버깅용)·가변저항 2종 으로 분리 제어 (9600 baud · 20ms 주기)

  • 저격총 3D 모델을 개별 파츠로 분리 제작하고 슬라이드 가변저항 위치(reloadValue > 80)와 당김/밀기 방향에 따른 실린더 Z축·탄피 배출(PopOut)·급탄(PushIn) 볼트 액션 및 BulletPool 재사용 구현
  • Tagger · WindController 로 레이캐스트 사거리와 중력·풍속 편차를 실시간 계산하고 사거리(dist)와 배율(Scope.ZOOM) 연동 탄착 마커 스케일 보정 적용

SharedPreferences 동기화 불일치 극복 — SQLite(sqflite) 전환 및 관계형 데이터 모델링

Flutter · sqflite · SharedPreferences · DatabaseMng · InfoMng
문제
초기에는 단순 Key-Value 저장소인 SharedPreferences 에 지출 목록을 JSON 문자열 형태로 직렬화하여 저장했으나, 화면에서 지출을 삭제해도 실제 로컬 데이터가 동기화되지 않거나 로컬 데이터가 변경되어도 화면 UI가 일치하지 않는 비동기 동기화 누락 문제가 지속 발생. 또한 카드별(cardID) 분리 조회, 잔여 한도 연산, 정렬 및 정합성 검증의 구조적 한계에 직면.
해결

02

단순 DELETE 배제 — 회계 무결성 보장을 위한 소프트 딜리트(Soft Delete) 및 상계 로그 기록

DatabaseMng.deleteUsage · DataCard · usage.removed
문제
등록된 지출 항목을 삭제할 때 SQLite에서 단순 DELETE 쿼리로 행을 물리 삭제하면 과거 지출 이력이 완전히 소실되어 사용자가 지출 취소 내역을 확인할 수 없으며, 카드 잔액 롤백 시 잔여 한도(remain) 계산의 정합성과 감사 추적성(Audit Trail)이 깨질 위험 발생.
해결
DatabaseMng.deleteUsage 에서 물리 삭제를 배제하고, 기존 행을 removed = 1 로 소프트 딜리트(Soft Delete) 갱신한 뒤 카드 현재 잔액을 즉시 환불(cur + cost) 처리. 동시에 환불 시점의 잔여 잔액을 기록한 신규 상계 레코드(removed = 2, 취소 내역)를 추가 삽입하여 회계 장부 방식의 영속적 이력 보존과 UI상의 취소 내역 시각화를 동시에 달성.

시스템 구조

  1. 01
    앱 초기화 및 DB 사전 로드 DatabaseMng.init · MultiProvider

    DatabaseMng 를 Singleton 및 eager 로딩(lazy: false)으로 구성하여 비동기 await init() 완료 후에만 하위 MultiProvider 와 화면 위젯 트리를 안전하게 마운트

  2. 02
    지출 기록 입력 및 프리뷰 동기화 AddScreen · CustomTextField · CreateUsageProvider

    소비 금액 및 항목 입력 시 CreateUsageProvider 가 변경 사항을 즉시 감지하여 상단 카드 프리뷰의 실시간 잔여 한도(remain)를 즉각 갱신

  3. 03
    관계형 로컬 DB 트랜잭션 기록 DatabaseMng (card · usage · custom · config)

    cardID 외래키를 기반으로 usage 테이블에 소비 레코드를 삽입하고, card 테이블의 cur 잔액을 원자적으로 차감하여 데이터 정합성 보장

  4. 04
    Provider 상태 통지 및 선택적 갱신 InfoMng · notifyListeners()

    DB 연산 완료 후 InfoMng 가 활성 카드 지출 리스트를 메모리에 갱신하고 notifyListeners() 를 호출해 필요한 위젯만 선택적으로 재렌더링

  5. 05
    리스트 인터랙션 및 애니메이션 렌더링 UsageListView · DataCard · flutter_animate

    flutter_animate 마이크로 모션으로 최신 지출 리스트를 시각화하고, AnimatedContainer 슬라이드 제스처로 우측 삭제 버튼을 노출

문제

문제

DataMng, OilMng, Mng, FileMng 등 8개 전용 Provider로 원시 배합 데이터, 원료 DB, 연산 엔진, 파일 I/O를 완전히 격리했습니다. 비누 4단계, 화장품 6단계 폼 입력 시 불필요한 리빌드를 억제하고, 12개 컬러 팔레트 중 4개 탭(비누·화장품·오일·설정)의 테마 색상을 독립 지정하는 디자인 시스템을 구축했습니다.

시스템 구조

  1. 01
    저장소 권한 확인 및 디렉토리 로드 permission_handler · FileMng.load

    permission_handler 로 외부 저장소 권한을 획득하고 UserData_Recipe/Beauty/Oil/Config 4개 전용 로컬 디렉토리를 초기화

  2. 02
    공정 선택 및 원료 투입량 입력 PageMng · OilMng · CustomTextField

    비누(CP/HP) 또는 화장품(토너/세럼/로션/크림)을 선택하고, 원료 DB에서 오일을 검색해 중량(g) 및 가성소다 순도·DC율을 단계별 폼에 입력

  3. 03
    화학 반응 배합비 & 지방산 산출 Mng.calculateLye · calculateWater · calculateFat

    NaOH/KOH 검화값 기반 필요 잿물량과 공정별 수분량을 연산하고, 10종 지방산 구성을 오일 비율로 가중 합산해 백분율로 정규화

  4. 04
    오프라인 로컬 영구 저장 FileMng.writeFile (.txt) · CSV Import

    계산된 레시피를 서버 없이 로컬 .txt 파일로 영구 저장하며, 대량 오일 데이터베이스는 CSV 파일 단위 파싱 및 마이그레이션을 지원

  5. 05
    다이나믹 결과 HUD & 차트 시각화 sResultView · circleChart · AnimatedContainer

    포화/불포화 지방산 비율을 circleChart 및 커스텀 바로 시각화하고, 4개 탭별 독립 테마 색상과 함께 부드러운 트랜지션으로 렌더링

  • 10종 지방산 조성 가중 합산 및 100% 정규화(Normalization) 엔진: calculateFat() 에서 오일별 라우르산·올레산·팔미트산 등 10종 지방산 벡터를 배합비로 내적 연산하고 총 중량 대비 100% 백분율로 정규화해 시각화

  • 12종 컬러 팔레트 및 4개 탭 독립 테마 디자인 시스템: 비누, 화장품, 오일, 설정 4개 메인 탭마다 사용자가 원하는 테마 색상을 독립 설정하고 AnimatedContainer 로 부드럽게 전환하는 맞춤형 UX 구현
